# PDF Strategy Experiment (P4.0, Closed)

Closed 2026-09-29 with [ADR-014](../../decisions/ADR-014-pdf-strategy.md). Host: Windows 11 Pro 26200, Python 3.14.7, PyMuPDF 1.28.2 (MuPDF inside the wheel). All documents are synthetic.

## Inputs

- `text-zh.pdf`: an ordinary-text page (heading, paragraphs, a bold and a red span, a URL) generated by `spike.py` with Microsoft YaHei.
- `deck-zh.pptx.pdf`: the PowerPoint fixture (`tests/fixtures/pptx/deck.pptx`) exported to PDF by native PowerPoint 16 (build 20326): title slide, bullets with a red run, an italic run and a hyperlink, a table, text in filled shapes, SmartArt and a chart.

Both live under gitignored `data/experiments/pdf/` and `data/acceptance/p4/local/`; `spike.py` recreates the first.

## Spike: Targeted Replacement

`spike.py` redacts each text block containing CJK (text only; images and line art kept), writes a fake 1.6x-length Latin translation with `insert_htmlbox` (span sizes, colors and weights, `scale_low` at the ADR-012 floor), saves, reopens and compares.

| Check | text-zh.pdf | deck-zh.pptx.pdf |
|-------|-------------|------------------|
| Blocks replaced | 4 | 10 |
| Fit / shrunk / overflow at floor | 3 / 1 / 0 | 2 / 6 / 2 |
| Source CJK characters left in the text layer | 0 | 0 |
| Image and drawing counts preserved | yes | yes |
| Sampled pixels changed outside text areas | 0 | 0 |

Findings that shaped ADR-014:

1. **Blocks are not units.** MuPDF put side-by-side table cells and two separate shapes on one row into one block, so their translations ran across cell borders. Units are now paragraphs of vertically stacked lines, split at short lines and list markers.
2. **`insert_htmlbox` writes nothing when the text does not fit at `scale_low`.** Two shapes came out empty. Production placement retries at floor sizes extending below the region, so text is never dropped (reported `overflow_at_floor`).
3. **Output size.** Embedding whole fonts produced 2.3 MB and 4.6 MB files; `subset_fonts()` brings a one-page test from 3.7 MB to 32 KB.
4. **Default HTML font is Charis SIL (serif).** Styles now always name a font: the provisioned original, a per-language substitute, or a generic family.
5. **Probes:** rotated pages work because extraction and `insert_htmlbox` share unrotated page coordinates. MuPDF's HTML layout falls back per glyph to Droid Sans Fallback for CJK. Redaction removes overlapping link annotations, so they are restored.

The editable-intermediate alternative (PDF to DOCX and back) was not built: the direct path showed no blocker that it would fix, and it would lose page fidelity on every document.

## Production Adapter: Acceptance Corpus

These runs use the production `formats/pdf` adapter through the real `doctranslator translate` CLI, zh to en, with both engines (SMALL-100 CTranslate2 int8; Gemma `gemma-4-31b-it` on the internal server), Windows and Office cloud fonts in the manifest, on 2026-09-29. Outputs, reports and renders are in `data/acceptance/p4/local/`.

| Document | Engine | Units | Fit | Notes |
|----------|--------|-------|-----|-------|
| deck-zh.pdf (4 pages) | Gemma | 16 | adjusted: 2 shape labels shrunk (18 to 17.0 and 14.8 pt) | bullets kept, link underline redrawn under the translated link text, table cells stay in their cells, chart and SmartArt shapes untouched |
| deck-zh.pdf | SMALL-100 | 16 | adjusted: 3 (18 to 14.7 and 13.2 pt; 33 to 27 pt) | same; one `formatting_fallback` |
| text-zh.pdf (1 page) | Gemma | 4 | adjusted: 2 paragraphs (12 to 9.8 and 11.3 pt) | the next paragraph limits growth: PDF never moves content below |
| text-zh.pdf | SMALL-100 | 4 | adjusted: 2 (12 to 9.8 and 11.6 pt) | |

Every run exited 0, passed the adapter's own output verification (translations present, no source text under them, page geometry unchanged) and left the inputs unchanged.

**Independent check with PDFium** (the PDF engine of Chrome and Edge, version 153.0.7999.0 (pypdfium2 5.13.0), via `scripts/pdf_independent_check.py`): all four outputs open, page counts and sizes match the sources, PDFium's own text extraction finds 0 CJK characters, and its renders match the PyMuPDF renders (translated text inside table cells and shapes, centered title and labels, red run and underlined link kept, chart intact). No Acrobat is installed on this host; Edge's viewer is PDFium.

Defects found and fixed during these runs, each with a regression test in `packages/core/tests/test_format_pdf.py`: bullets merged into one paragraph; a centered title treated as left-aligned and overflowing; glyph-fallback font switches splitting words into tagged spans ("China" + "South"); link underlines left behind at the old position; the second bullet's marker dropped by the engine; link annotations deleted by redaction.

## Supported Cases and Limits

| Supported | Reported, left untranslated | Rejected |
|-----------|-----------------------------|----------|
| Horizontal text with a Unicode mapping, in paragraphs, lists, table cells, shapes and free text; inline size/bold/italic/color/underline; rotated pages; links (restored); images and vector art kept | Rotated or vertical text (`pdf_rotated_text_kept`), unmapped text (`pdf_text_unreadable`), image-heavy pages (`untranslated_image_content`) | Encrypted, signed, no extractable text (`no_extractable_text`), unreadable |

Known limits: paragraph detection is heuristic; growth is limited to the free space around each unit, so dense text shrinks more than in Office formats; link rectangles do not follow moved text; form fields, annotations' own text and optional content layers are not translated.
