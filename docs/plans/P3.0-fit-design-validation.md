# P3.0 - Fit Measurement and Font Design

Status: Draft architect task. Parent: P3, [Feature #9011](https://chintand.visualstudio.com/AI%20Projects/_workitems/edit/9011). Does not approve a renderer, font distribution method or shrink defaults.

## Objective

Select a text measurement/font strategy that can implement the README's relative-to-original fit guarantee for PPTX, DOCX fixed elements and XLSX without importing format libraries into `fit/`.

## Relevant Architecture and Dependencies

README visual-quality contract; ADR-003; core architecture section. P2 must settle document/container references and preservation behavior before production fit code begins. Research can proceed against synthetic fixtures while P2 is developed.

## Files Expected to Change

One proposed ADR for measurement/fonts, an experiment/report under `docs/experiments/`, the core architecture section after acceptance, and the [P3 implementation plan](P3-fit-check.md). No production fitter in this design task.

## Steps

1. Build a small matrix of Chinese/English/Japanese/Spanish text with source overflow, translation growth, explicit breaks, rich runs, bullets, rotation, margins, merged cells, wrap/no-wrap and missing fonts. Include DOCX body text as a negative control that must never shrink.
2. Compare candidate layout engines against native application rendering on those fixtures. Measure wrapping and glyph extents, not characters. Record installed fonts, fallback differences, shaping/bidi needs, licensing, runtime footprint and portability. Do not select based only on one Latin font.
3. Specify font provisioning inside the company network, deterministic fallback and missing-font diagnostics. Decide whether unverifiable measurements fail, skip with an unresolved issue, or require native rendering; no invented precision.
4. Define container coordinates, padding, original rendered extent and allowed-space comparison. The allowed space is the larger of original extent and container bounds. An original overlap/overflow is never treated as a new defect. Specify multi-run scaling and which properties an adapter may modify.
5. Choose minimum size, minimum relative scale, shrink steps, measurement tolerances and fallback behavior from evidence. Define an unresolved result at the floor, with stable locations and original/final sizes. Do not equate a geometric pass with visual approval.
6. Draft exact `LayoutSupport`, measurement, font-resolution and fit-report contracts. Include strategy/font identity and options in output fingerprinting, including migration from P2 `fit_status=not_run`.

## Tests and Completion Criteria

- [ ] Native comparison evidence covers all required container types and the four languages.
- [ ] Measurement/font ADR accepted and numerical tolerances/defaults pinned.
- [ ] Missing-font, original-overflow, floor and mixed-run behavior specified.
- [ ] Format adapters own geometry/property changes; generic fit code remains format-neutral.
- [ ] Detailed P3 tasks, fixtures and acceptance criteria are ready for coder handoff.

## Out of Scope

PDF strategy (P4), general page redesign, cross-element font-size equalization, OCR and MCP visual editing. P4 planning begins after the measurement decision, using its own PDF strategy experiment/ADR.
