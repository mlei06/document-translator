# Unified translation core and CLI implementation evidence

Scope: common target-only inference, automatic policy types, bounded transport, and removal of production rendering from the core and CLI. The current owner specification in `unified-translator-design.md` takes precedence over older source-dependent and thorough-fit contracts.

## Implemented decisions

- `AutomaticTranslationPolicy` is a public core model used by product callers. Its default is `web-auto-v2` and the exact six-model Davy order followed by `hy-mt-local`. Candidate fingerprints and ordered IDs participate in a deterministic policy digest. Invalid, missing, duplicate and unapproved IDs fail validation. Deliberate reorderings of approved IDs remain representable for pinned-policy upgrades. Website configuration must additionally check configured model binding, including Gemma's actual model name, and local fallback readiness.
- Davy uses `llm-target-only-v2`; HY-MT uses `hy-mt-target-only-v3`. Both accept target-only calls and render the same payload regardless of optional legacy source arguments. HY-MT uses the specified English base instruction for every target and preserves necessary inline tags.
- The text/document pipeline no longer rejects or skips equal source/target content, no longer uses detected source script to suppress other language passages, and treats detection errors as optional metadata. Unsupported-script metadata is Unknown rather than falsely claiming no text. Detector strategy and source values do not participate in output fingerprints. Explicit CLI source arguments remain accepted for the continuing legacy CLI contract, but cannot influence automatic prompts or compatibility.
- Public `Translator.translate_document` and the pipeline accept optional `detection_metadata` (`DocumentDetection`). Workers reuse ingestion metadata from the pinned work's separate metadata entry for every fallback rung, including Unknown. Metadata never enters source prompt arguments, policy digest or output compatibility. Detection runs locally only when no ingestion metadata is supplied (for example a standalone CLI invocation). Persisted metadata may omit an unavailable segment count rather than invent one.
- Transport makes at most three attempts per request. Each of its at most two backoffs is at most 30 seconds, so total retry backoff is bounded at 60 seconds. Request timeouts are finite. Structured hard quota/policy denials raise `EnginePolicyDeniedError`, distinct from transient overload and authentication failure, without exposing upstream content.
- Shared endpoint connection/proxy failures use `EngineEndpointUnavailableError`; model request timeouts remain `EngineUnavailableError`, allowing the worker to advance only the affected rung. Incomplete/refused structured responses cannot become successful outputs.
- Architect-approved managed HY-MT identity uses a verified lowercase SHA-256 digest of weights/runtime/settings via `managed_runtime_identity`. This is allowed only for server-local HY-MT. The digest replaces the ephemeral loopback endpoint in producer identity while model, deployment and decoding remain pinned; ordinary remote and administrator-managed endpoint identity is unchanged.
- Real Davy inspection found plain GPT-OSS emits a leading `<thinking>...</thinking>` envelope before otherwise valid structured JSON. The parser now accepts exactly one bounded, balanced leading envelope, then still validates the complete remaining JSON response/count/schema. Nested, repeated, unclosed, oversized and trailing-junk forms fail; literal tags inside JSON strings remain unchanged. Output identity pins `llm-response-v2-thinking-envelope`; prompt text did not change for this protocol normalization.
- When the provider supplies `response.model`, it must equal the requested model or a fingerprinted explicit `response_model_aliases` entry; unexpected identities fail without fallback. Observed Davy thinking requests report `gpt-oss-120b`, so generated Davy thinking configuration pins that one alias. Compatible endpoints omitting this optional field remain identified by configured deployment only; omission is not presented as independently verified producer identity.
- Removed core renderer implementations, public rendering functions/configuration, rendered verification metadata, thorough fit, and CLI `--fit-mode`. Native standard fit and saved-file verification still run for all supported document adapters. The empty `render` namespace remains solely to preserve the existing import-boundary contract, not executable rendering capability.
- Obsolete tests for removed rendering behavior were replaced with explicit removal-contract tests. Existing saved-file, layout, protected-content and PDF verification tests remain.

## Independent shared-work review fixes

- A newly verified upload cannot attach to already-cancelling shared work. Replacement work advances the slot generation, preserves the old attempt's reservation until cancellation acknowledgement, and keeps the two executions separate.
- Publication checks active work identity and slot generation inside the fenced transaction before recording success. Late output cannot silently succeed when its slot was replaced.
- Failed higher-ranked attempts followed by reuse now report the actual cached producer, successful cache-hit status and no stale error. Immediate cache hits also identify the real producer.
- Terminal obsolete work still releases its own reservations and synchronizes its own waiters without mutating a replacement slot.
- Added shared REST regressions for cancelling-work replacement, generation fencing, reused producer truth and exhausted-rung restart. Existing queue test clock now anchors after admission rather than assuming all submissions finish within five seconds, eliminating host-load flakiness while preserving explicit lease time advances.
- Shared REST and queue acceptance after these fixes: 25 passed.
- Detection handoff acceptance: 37 focused core/shared tests passed; detector invocation is exactly once at intake and remains once after whole-document fallback, including unknown source metadata. `DocumentOut` accepts unknown/mixed status rather than failing response validation.
- Shared admission now enforces the existing global queue bound only for new execution. Joining active work remains possible; a compatible current result remains downloadable when optional upgrade queue/storage capacity is unavailable. Cached waiters copy the current result's actual fit status.
- Storage publication verifies an existing digest after a failed filesystem replace, preventing a failed repair from reporting corrupt bytes as successfully stored. Added corruption repair and failed-delete retry coverage, including keeping undeleted bytes charged.
- Additional REST/storage regressions cover fresh-upload multipart idempotency, final waiter batch cancellation, corrupt current-output availability, active reservations older than 24 hours, and backup/restore preserving current outputs and private grants while excluding outstanding originals.
- Final shared/storage edge suite: 31 passed, plus the subsequently added verified-upload repair/coalescing E2E test passed. Focused Ruff and Pyright passed after the changes.
- Daily backups hold a unique named leader lease across sizing, pending cleanup, snapshot, publication and rotation. A concurrent supervisor cannot delete another run's pending tree; failure releases the lease. The concurrency/retry regression passed, as did warm-cache original removal and three policy binding/order tests.
- Independent desktop asset review added resolved-path guards against managed staging symlinks/junctions and canonical case-insensitive manifest duplicate rejection. HTTP transport regressions cover interrupted validator-bound resume, mismatched validator/range restart, cancellation resume, full hash/size validation, traversal rejection, failed load without activation, and preservation of user-owned files behind an actual Windows junction. Asset plus existing desktop suite: 20 passed, zero skips. These tests do not claim real-model load quality or signed installer acceptance.
- The shared `DocumentRunner` protocol exposes execution-time availability for every runner, including the managed desktop adapter. Workers no longer restrict discovery to the catalog adapter's concrete class. Missing advertised models advance without inference; an empty discovered set exhausts cleanly. Cache hits remain outside runner discovery.
- Discovery correction validation: shared/queue suite 41 passed; all four focused discovery regressions passed, including the subsequently added actual desktop adapter regression. Focused Ruff and Pyright passed.
- Reproduced deleted/expired History resurrection in two REST cases before fixing it. A fresh verified upload now replaces a revoked or expired grant with a new ID and detaches obsolete waiters. Old History and cached-job download URLs remain revoked permanently; retained unexpired grants still regain downloads when an evicted slot is recreated.
- Consequential metadata retention choice: use the existing `job_retention_days` grace after grant revocation (automatic expiry occurs at last submission plus 90 days). Sweeps physically remove up to 500 expired tombstones and up to 500 old empty slots without grants, current output or active work. This bounds abandoned metadata while preserving live private grants and shared output reuse.
- Desktop concurrent submit reproduction forced both requests past the preliminary replay read; the second identical request incorrectly failed queue admission. The serialized desktop admission transaction now rechecks submission identity before queue checks or reservations. Regression verifies one job, one reservation pair, replay under queue pressure and mismatched-content conflict.
- A bounded HEAD request to the exact approved pinned HY-MT Hugging Face model URL returned HTTP 302 to `us.aws.cdn.hf.co` without downloading model bytes. Asset download now follows at most five HTTPS redirects, rejects downgrade/URL credentials, and builds fresh requests without cookie/authorization forwarding. Resume headers survive redirects; final bytes still require manifest size/hash and runtime load validation. Regression covers safe CDN download, downgrade/userinfo denial, redirect loop bound and interrupted validator-bound resume through CDN redirects.
- Desktop retention regressions exercise actual job expiry and journal pruning while preserving the original and a user-edited export. Corrupted installed weights/runtime/revision yield sanitized Needs attention and exclude the local model. Reproduced a malformed journal entry terminating the export thread; schema validation and per-record error handling now preserve damaged metadata for repair and allow independent ready exports to complete. Lifecycle/offline regression suite: 14 passed.

## Limits of this evidence

Mock transport results verify routing inputs and error contracts, not translation quality. Real Davy acceptance and model quality for every approved rung require authenticated approved-network endpoints. Signed desktop installation, managed HY-MT binaries/model assets and clean-machine proofs are outside this core/CLI slice and must be reported separately. No production publication or deployment was performed.
