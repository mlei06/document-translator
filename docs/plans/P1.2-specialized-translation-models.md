# P1.2 — Optional TranslateGemma and HY-MT2 profiles

Scope authorized by the owner's 2026-09-28 request to integrate and optimize these
families instead of T5-small. This is additive experimental integration, not a
replacement of the accepted SMALL-100 or internal Gemma defaults.

## Architecture contract

Reuse `LlmEngine` for self-hosted OpenAI-compatible endpoints. Keep HTTP/TLS in
`engines/llm.py`, settings in each app, and formatting independent of engines.
Expose `translation_profile = generic | translategemma | hy-mt2` through core
configuration and both CLI/eval settings. The generic profile retains its exact
request and output identity behavior; SMALL-100 is unchanged.

Specialized profiles issue one text segment per request, concurrently with a
bounded queue. They do not use the generic system prompt or JSON batch response.
HY-MT2 uses its documented plain translation instruction on `/chat/completions`.
TranslateGemma uses `/completions` with the exact text branch of Google's native
template (revision `10042cb0e6e7fdce748996a71dc3dc432a4e0c89`), pre-rendered
with language names/codes and Gemma control tokens. This preserves language metadata
that chat adapters can discard. The server must recognize those special tokens.
Its chat parser is unused; llama.cpp requires disabling that parser at startup.

Require a nonblank deployment revision for specialized profiles. Identify model
weights/quantization, runtime and template revision operationally. Include profile,
prompt version and decoding parameters in output identity; never include secrets.
Reject blank, malformed, refused or length-limited responses. Preserve segment
ordering and propagate failures rather than returning partial translations.

Expose output limit, concurrency, temperature, top-p, top-k, repetition penalty
and seed. Defaults favor deterministic experiments (temperature zero), not a claim
to reproduce vendor benchmark scores. HY-MT2 vendor sampling settings can be
selected explicitly. Model-serving software remains outside the Python lockfile.

## Baseline boundary

P1.1 requires full current-model baselines before prompt/model changes. The owner
now explicitly requests additional-model development; proceed with optional
profiles while preserving current behavior. Full FLORES+/COMET and current-model
baselines still gate any default replacement or quality superiority claim.
Synthetic smoke/timing examples are not quality baselines. Do not export them as
accepted baselines or alter old benchmark provenance.

## Local validation

1. Run all six repository checks and mock transport tests of the new contracts.
2. Download pinned official HY-MT2 GGUF artifacts and verify published SHA-256.
3. Run a loopback-only llama.cpp CUDA server; verify translation through the core
   and document CLI. Measure fixed-workload warm throughput across concurrency and
   Q8/Q4 settings, retaining outputs to reveal translation differences.
4. Validate TranslateGemma against its official files when access is available.
   Gated access or incompatible server templates remain explicit limitations.
5. Record hardware, model/runtime hashes, prompt/decoding settings, timings and
   checks. Keep raw local artifacts in ignored `data/`.
