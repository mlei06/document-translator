# P2.0 - Validate Document Design Decisions

Status: Draft architect task. This task produces the exact technical contract before production coding under the P2-P6 handoff. Resolves the open gates in the [P2 draft](P2-document-translation-and-cli.md), then returns an implementation contract for architect review.

## Objective

Make the document-formatting and preservation decisions with evidence before coders build the pipeline. Preserve the README's fidelity requirements; do not substitute a convenient fallback for an approved product contract.

- README format/translation requirements

## Dependencies

Existing engine API and synthetic source material. Real LLM/MT calls need the configured internal/local backends. Any change to production prompt or model first requires P1.1. Baseline capture itself is a separate operational task, not an excuse to modify the prompt during a spike.

## Files Expected to Change

Experiment scripts/reports under `docs/experiments/`, proposed ADRs, P2 plan and, after approval, the core architecture section and README. Temporary outputs stay under `data/experiments/`. No production adapter or engine modifications in this task.

## Steps and Decision Gates

1. **XLSX write strategy:** use the completed eight-case experiment as evidence. The owner has selected preserved sheet names and literal cell-text translation; no rename option is in scope. Finalize ADR-009's remaining writer/calculation contract. Exercise label-dependent formulas in native Excel or LibreOffice, with external links disabled, and decide cache invalidation/recalculation behavior. Check output opens without repair and capture representative source/output views. The core must not claim to evaluate formulas.
2. **Formatted translation:** preserve the prior tag-spike evidence with its limited scope. Add reproducible mixed-run cases covering all 12 directions, literal `<`/`&`/tag-like text, hyperlinks, tabs/breaks, protected spans, nested markup, repeated text with different formatting, and moved emphasis. Evaluate paragraph tagging with the current LLM prompt. For MT compare formatting-span translation with a paragraph/alignment approach, measuring meaning and formatting correspondence separately. Do not choose tag stripping plus first-run assignment. A deterministic fallback can preserve source runs, but must have an accepted quality policy and a visible diagnostic. Pin exactly one production strategy and its failure behavior before P2.2.
3. **PPTX/DOCX serialization:** generate minimal fixtures for every required surface, including grouped shapes, notes, headers/footers, footnotes, hyperlinks and fields. Change text, reopen, compare structural invariants and inspect representative native renders. Decide whether library serialization is sufficient or the adapter must patch selected OOXML parts. Unknown content must survive or produce a preflight rejection, never disappear silently. XLSX results do not prove the other formats safe.
4. **Source detection and pass-through:** choose and pin one offline detector that works on the selected Python version. Restrict candidates to zh/en/ja/es, benchmark short/ambiguous and mixed-language documents, and specify the ambiguity rule. Kana/Han heuristics alone cannot distinguish Japanese text without kana from Chinese. Define token protection for numbers, URLs, email, paths, code and explicit product-name terms; general automatic product-name recognition cannot be promised without evidence.
5. **Finalize the contract:** resolve all gates listed in P2, choose resource-limit defaults from bounded fixture trials, specify normalization/placeholder validation and engine identity for fingerprinting, and write the final types/signatures into the core section of `docs/Architecture.md`. Cache fingerprinting at submission must not instantiate today's MT `Translator`, which loads weights: define metadata-only identity preparation and a worker check that the loaded runtime matches it. Document known unsupported constructs and diagnostics. No coder should have to choose a text-alignment model, language detector or XLSX reference policy.

## Interfaces

The proposed signatures and ownership in P2 are the starting point. The output of this task is a reviewed design, not an alternate public API implemented in a spike. Keep engine/format libraries in their accepted module boundaries.

## Tests and Completion Criteria

- [ ] Approved preserved-sheet-name policy applied; recalculation/writer contract validated with native-open/visual evidence. An outstanding native gate prevents completion.
- [ ] Formatting strategy selected for both engines with reproducible evidence; no silent run flattening.
- [ ] PPTX/DOCX save strategies proven on required content surfaces.
- [ ] Detector, ambiguity rule, token protection and resource limits pinned.
- [ ] Technical ADRs accepted after evidence review; owner-approved README amendment applied. Any new product exception is escalated.
- [ ] P2 and core architecture section agree on exact contracts and acceptance tests; no unresolved architecture decisions are delegated to coders.

## Out of Scope

Product adapters, CLI implementation, fit algorithms, PDF, server work, new model selection and large-scale parallel agent orchestration.
