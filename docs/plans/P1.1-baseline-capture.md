# P1.1 - Capture Deferred Quality Baselines

Status: Draft operational plan. Implements the owner's existing baseline deferral; does not put baselines back into P1's completion criteria. Required before the first prompt, LLM model or MT model change.

## Objective

Record full FLORES+ baselines for the current Gemma prompt/model and SMALL-100 configuration so later changes have a trustworthy regression reference.

## Relevant Architecture

- [ADR-005](../decisions/ADR-005-translation-quality-evaluation.md), [ADR-006](../decisions/ADR-006-mt-model-selection.md)
- [Eval component](../Architecture.md#evaluation-reference), [P1 step 11](P1-translation-engines-and-benchmark.md)

## Dependencies

- A clean committed checkout containing the current engine behavior. The baseline exporter rejects a dirty source tree. Do not falsify that field or discard another agent's changes to make it clean; finish the normal review/commit workflow first or use an isolated checkout of the reviewed commit.
- Company-network LLM access and locally configured secrets, converted SMALL-100, pinned FLORES+ data and enough disk for COMET's isolated dependencies/model.
- No prompt/model modifications before both reference runs are captured. The XLSX serialization spike uses no engines and does not trigger this gate.

## Files Expected to Change

- Machine-produced `apps/eval/baselines/llm.json` and `mt.json`, generated by the eval command, never hand-edited.
- ADR-006 scores and the roadmap's deferred-work evidence; no dataset text or credentials.

## Implementation Steps

1. Record source commit, clean status, configured model/prompt identity, MT conversion provenance and available disk. Read settings through the existing app without printing secrets. Run both marked integration tests with their settings present; count skips separately.
2. Confirm the pinned dataset has 1,012 aligned examples per language and all 12 directions. Use the existing downloader only if missing.
3. Run both translations before creating tracked baseline files, so both manifests describe a clean source tree:

   ```powershell
   uv run doctranslator-eval run --mode llm --directions all
   uv run doctranslator-eval run --mode mt --directions all --mt-model-dir data/models/alirezamsh--small100-ct2-int8 --mt-family small100
   ```

4. Retain the returned run paths. If scoring fails after translation, use `uv run doctranslator-eval score <run_dir>`; do not repeat translation unnecessarily. Do not introduce resume infrastructure for this one-off task.
5. Verify both manifests are complete, unrestricted by `--limit`, on the intended commit, and contain the same pinned dataset, all 12 directions and 1,012 scores each. The current exporter checks completion/dirty state/limit but does not itself enforce all-direction coverage, so verify that explicitly.
6. Run `uv run doctranslator-eval baseline set <run_dir>` for each. Compare each produced baseline with its own source run and itself; expect no significant difference and exit code 0.
7. Record per-direction COMET/chrF and run IDs in ADR-006/the completion record. Review the generated files for scores/IDs/metadata only. Commit through the ordinary review workflow; never manually edit generated scores.

## Interfaces and Edge Cases

Only the existing eval CLI is used. Do not change model/prompt settings while collecting references. Network or scoring errors remain visible and do not turn into a partial baseline. A limited smoke run or two sentences in the target script is not a quality baseline. Domain-data sourcing remains open and does not block the FLORES+ reference.

## Tests and Completion Criteria

- [ ] Both real integration tests run successfully without skips.
- [ ] Both full runs complete with pinned data and recorded provenance.
- [ ] Both baseline files are generated, checked and committed with no text or credentials.
- [ ] Self-comparisons pass and ADR-006 records the MT reference scores.
- [ ] All six repository checks pass; CI evidence is attached to the reviewed change.

## Out of Scope

Prompt/model tuning, model bake-offs, domain-set creation, document fidelity scoring and new benchmarking infrastructure.
